# DECISIONS.md

Autonomous build log. Every point where a question would otherwise have been
asked is resolved here with the choice and the reason, optimizing for the two
Track-1 judging criteria: (1) third-party verifiable without lab-network access,
(2) a lab would actually adopt it.

| # | Decision | Why |
|---|----------|-----|
| D0 | Repo lives at `sole-egress/` as its own git repo; removed an accidental parent repo. | §4 names the repo `sole-egress`. |
| D1 | Report toolchain: Typst (installed via `pip install typst`, a self-contained wheel) — no LaTeX/pandoc present on the machine. If Typst is unavailable at render time, fall back to a 2-column HTML→print PDF and note it. | Apart's official template is not machine-fetchable (submission page gives no template URL; the OpenAI/HF pages 403). A clean 2-column academic layout is the honest substitute; §1 permits this with a DECISIONS note. |
| D2 | Attestation: primary third-party-checkable artifact is an **append-only hash-chained transcript** the verifier recomputes, plus recomputation of the public lockfile digest and probe-suite digest. An Ed25519 signature is added **only if** `cryptography` is importable; otherwise the report ships with an HMAC tag over the transcript root and documents that identity-signing needs the optional dep. | Python stdlib has no asymmetric signing. The hash chain is what actually answers judging criterion 1 — a third party recomputes it from the public repo and learns nothing about the lab network. Signature is identity icing, not the integrity mechanism. |
| D3 | Two transports, one probe suite. Probes are transport-agnostic: Config A hands them an HTTP forward-proxy endpoint; Config B hands them a broker unix-socket path. | Keeps the probe suite honest — the same 12 probes face both worlds, so the A-vs-B table is apples-to-apples. |
| D4 | `sole-verify run --all` orchestrates **Docker Compose** (satisfies DoD #1). A `--local` mode runs the identical probes against host-spawned processes (proxy on loopback, broker on a unix socket) for reproducibility when a Docker daemon is slow/unavailable. Both write byte-identical result schemas to `results/`. | DoD #1 requires compose; but the numbers must be reproducible by a judge on any laptop. Local mode is the fallback path, documented, not the headline. |
| D5 | Covert-channel receiver model: a **compromised upstream** observing the broker's upstream fetch pattern (which pinned entry, in what order, with what timing). Capacity measured empirically by transmitting a known secret via request selection + ordering + inter-request timing and counting bits that survive the broker's caching + rate limit. | §3/control 9 require bits/hour *measured*, not asserted. The compromised-upstream receiver is the residual channel that SEP-1 cannot close by construction — the honest thing to quantify. |
| D6 | Mock upstream is "compromised-but-cooperative": proxies arbitrary requests, honours redirects, accepts uploads, returns whatever is asked. It contains **no exploit** — it simply says yes to everything, which is the incident's own assumption ("the one permitted egress is compromised"). | §0.1 no-exploit rule. The finding is about the monitored *property*, not about any vulnerability; a cooperative yes-machine is sufficient and weaponizes nothing. |
| D7 | 12 probes (target 10-14), 11 SEP-1 controls in profile (target 8-12 — §4 lists 10 numbered; we add No.11 environment-isolation + fold response/redirect to reach a mechanically-testable set). | Hits the required counts with every item mechanically testable. |
| D8 | Exploit mechanism inside the cache proxy: §2 says treat as not-established. Post-build web research (OpenAI Black Hat, Aug 5 2026) later disclosed a chain (SSRF → legacy token-refresh RCE → Groovy plugin). We record this as a *contested / later-disclosed* class in claims.json and still write SEP-1 exploit-agnostic, because (a) it was unknown at HF disclosure, (b) nine chained CVEs is precisely why per-exploit patching is the wrong layer. | Evidence discipline (§6) + the exploit-agnostic requirement (§2) both hold; the late disclosure strengthens the class-closure argument rather than weakening it. |
| D9 | Date conflict (sprint page "11-13 July" vs HF timeline "9-13 July") is reported, not resolved; classed `contested`. | §2 explicit instruction; it is the evidence-discipline demonstration. |
| D10 | Headline channel figure is the **deterministic rate-limit bound** (216,000 bits/hour), not the wall-clock measurement (which drifted ~0.5%). Empirical figure reported as confirmation. | The §9 self-review found the wall-clock number irreproducible run-to-run; a headline a judge re-runs must be stable. See VERIFICATION.md S1. |
| D11 | `run --local` is a single-run tool on fixed ports + one `results/` dir; concurrent runs corrupt shared state by design. Documented rather than re-architected (untested code change deferred while command execution is unavailable). | The §9 subagent's apparent `verify` nondeterminism was diagnosed as two overlapping runs (its + the main session's), not a single-run defect. See VERIFICATION.md H1. |

## One-month follow-up

| # | Decision | Why |
|---|----------|-----|
| D12 | Week-1 workload is a **benign fixture project** (`workload/`, `tidyreport`: CSV → stats → text table) with a 17-package closure across runtime, build-backend and test-extra groups, served by the same mock upstream under an `fx-` prefix and pinned in its *own* lockfile (`workload/lockfile.json`). Wheels are byte-deterministic zips. | Realistic dependency shape (transitive chains up to depth 4, build and test groups that CI only reaches after earlier phases pass) without touching a real index or any vulnerability content. Keeping it out of the main lockfile leaves the headline digest `c62ba9e2…` and every Track-1 number unchanged. |
| D13 | Friction is measured on a **naive seed lockfile** (direct runtime deps only) under two fix strategies: *error-driven* (amend exactly what the broker logged as `lockfile_miss`, rerun) and *closure* (`lockfile_amend --manifest --closure`, one pass). Headline = deterministic counts (runs to green, fail-closed events per phase); wall-clock time-to-fix is reported but not headlined. | Same D10 discipline: a judge must be able to reproduce the number. The two strategies bracket real lab behaviour (fix-from-the-error-message vs. a proper lock step). |
| D14 | `lockfile_amend` is **lab-side, between runs, append-only**: it reads misses from the *broker transcript* (not the sandbox's own report), never re-pins an existing key, reports drift if upstream bytes changed, and labels new pins TOFU unless `--expect` cross-checks them. Each broker lockfile load is a transcript `note`. | An auto-amending broker is live resolution — the open door S4 closes. Treating sandbox-reported misses as untrusted and refusing re-pins means a compromised upstream or a scheming workload cannot use the amend path to widen the closure silently. |
| D15 | Multi-tenant broker = **one independent `Broker` per tenant** (own lockfile, transcript, cache, rate limiter) behind one process, with **tenant identity bound to the socket**, never to request data. The closed grammar is unchanged, so a `"tenant"` field is a `grammar_violation`. | Isolation by construction rather than by an access-control check that has to be right: there is no code path where one tenant's lockfile, cache or transcript is consulted for another's request. Per-tenant caches also mean one tenant's fetch history leaves no state another tenant can observe. |
| D16 | Per-tenant **quota = max upstream fetch attempts per sliding window**, counted at attempt (including failed/mismatched fetches), checked *before* contacting upstream; cache hits are free. The quota is verified from the transcript alone, and the per-tenant channel figure is a **config-derived upper bound** `quota × (log2|L| + log2(window/min_interval))` bits/window, not a measurement. Recommended setting: quota = \|lockfile\| per window, enough for a full cold resolve with a caching broker (shown by running the Week-1 workload as tenant `beta`). | Bounds the number of upstream-observable events per tenant by configuration, which a third party can check, rather than relying on observed behaviour. The bound deliberately counts both selection and timing per event, so it is conservative. |
| D17 | Reference CI gate is a **composite action at the repo root** (`action.yml`, so adoption elsewhere is `uses: georgxzh/sole-egress@<sha>`) plus `.github/workflows/sep1.yml` (`uses: ./`). Steps: run harness → `verify` → **self-test that a tampered report is rejected** → job summary + evidence artifact → gate fails the job unless `verified=true`. Verify failure does not short-circuit, so evidence is always uploaded. `concurrency` serialises runs per ref (fixed ports, D11). Validated locally with a step-by-step simulator of the composite action (pass case green; altered-report case fails the job); the first real GitHub run happens on push. | A gate that can't fail is decoration: the self-test proves on every run that `verify` still rejects a forged report. Pinning third-party actions by major tag is the GitHub default; labs adopting it should pin by SHA. |
| D18 | **Verifier hardening found by the Week-4 CI test:** `verify` previously trusted the report's own `prediction_held` flag, so a report claiming a Config B probe `SUCCESS` still verified. It now recomputes `outcome == expected`, checks each `expected` against the *public* probe suite, checks the probe set is complete, and cross-checks the Config B outcomes that leave broker evidence (`smuggle_grammar`, `poisoned_artifact`, `lockfile_miss`) against transcript verdicts. | Exactly the "instrumentation reporting success is not evidence" failure the paper is about, in our own verifier. Remaining outcomes with no broker-side evidence are still self-reported, which is limitation 8 (runtime honesty), unchanged. |
